Training & alignment pipeline

An assistant is a pretrained next-token predictor reshaped by a stack of post-training stages, each with its own data, loss and characteristic failure. Knowing which stage produced a behavior tells you which lever can change it.

In this chapter Trace the pipeline from curated tokens to a deployed assistant, derive what SFT, RLHF, DPO, RLVR, distillation and LoRA each optimize, and predict how each one fails.

Why the pipeline matters

  • Attribution: sycophancy, refusals, verbosity and confident reasoning errors each trace to a specific stage and signal. Without that map you patch symptoms in prompts.
  • Model selection: "base", "instruct", "reasoning" and "distilled" checkpoints differ in which stages ran. That predicts how they take prompts, templates and fine-tuning.
  • Your own tuning: a LoRA run or a DPO pass is a small post-training stage. It inherits every failure mode below, at a scale where you own the eval. Whether to tune at all is covered in fine-tune vs RAG vs prompt.

Mechanism

Pretraining buys capability with compute. Every later stage spends far less compute to move probability mass toward behaviors someone can label, rank or verify.

  1. Pretrainnext-token loss on trillions of curated tokens
  2. Mid-traincontinued pretraining on a higher-quality, domain or long-context mix
  3. SFTimitate demonstrations in a chat template, loss on response tokens
  4. Preference + RLRLHF, DPO or verifiable rewards, KL-tethered to a reference
  5. Distill / adaptcompress into students, LoRA for task deltas

How it works

  • Objective: minimize the over every position. No labels, no task: capability is whatever helps predict text.
  • Curation is most of the work: URL and language filtering, heuristic and classifier quality filters, exact and near-duplicate removal (MinHash-style), PII and toxicity filtering, and decontamination against eval sets. Duplicates waste compute and raise memorization.
  • Compute-optimal scaling: training FLOPs are roughly 6 × params × tokens. Chinchilla found params and tokens should grow equally, about 20 tokens per parameter: 70B on 1.4T tokens beat 280B Gopher at the same compute.
  • Overtraining is deliberate: Chinchilla optimizes training compute, not serving cost. Meta reports Llama 3 8B kept improving far past its ~200B-token optimum, on over 15T tokens, because a smaller model is cheaper for every future request.
  • Mid-training: continued pretraining with the same loss on a reweighted mix, typically more code, math, synthetic reasoning or domain text, often with long-context extension and a decaying learning rate. Recipes are lab-specific and sparsely published.

Trade-offs

  • pro: the only stage that adds broad knowledge and skill at scale.
  • con: the result is a document continuer: it may answer a question with more questions. Base models need few-shot prompts.

How it works

  • Data: prompt-response pairs and multi-turn dialogs, human-written or model-generated then filtered. Small curated sets shift format and tone; quality and coverage beat volume.
  • : turns are serialized with role markers and an end-of-turn token. The model learns to emit that stop token; serve with a different template and it rambles or leaks role tags.
  • Loss masking: the same next-token loss, but prompt, system and user tokens get label −100 (ignored). Gradient flows only from assistant tokens, so the model learns to answer, not to imitate users.

Trade-offs

  • pro: stable, cheap, easy to debug: the loss is a direct likelihood.
  • con: imitation caps quality at the demonstrations and teaches confident style even where the model lacks the knowledge, one driver of hallucination.

How it works

  • Shared objective: maximize E[r(x, y)] − β · KL(πθ ‖ πref). The keeps the policy near the reference so it cannot drift into text the reward was never trained on.
  • RLHF (InstructGPT recipe): fit a reward model on ranked pairs with a Bradley-Terry loss, then run PPO: sample responses, score them, update with a clipped policy gradient and a learned value baseline. Four models live in memory: policy, reference, reward, value.
  • DPO: the KL-constrained optimum implies reward = β · log(πθ/πref) up to a per-prompt constant. Substituting into Bradley-Terry gives loss = −log σ(β[(log-ratio of chosen) − (log-ratio of rejected)]). No reward model, no sampling.
  • DPO intuition: push up the chosen response's likelihood relative to the reference and push down the rejected one's. Each pair's gradient is weighted by how wrongly the implicit reward currently orders it.

Trade-offs

  • gotcha con: . A learned reward is a proxy; PPO finds its blind spots, commonly length, flattery and agreement with the user. Watch proxy reward rising while held-out human preference falls.
  • con: DPO is offline. It never sees its own new mistakes, can lower the absolute likelihood of both responses while widening the margin, and is sensitive to β and to how far the pairs sit from the policy's own outputs.

How it works

  • Signal: a program, not a person, scores the output: exact-match math answers, unit tests for code, schema checks. DeepSeek-R1-Zero used only rule-based accuracy and format rewards, explicitly avoiding neural reward models for reasoning because they get hacked at scale.
  • GRPO: sample a group of G answers per prompt and set each one's to (ri − mean(r)) / std(r). The group mean replaces PPO's value network, saving memory; a KL term to a reference remains.
  • Emergence: with enough steps, response length grows and self-checking, backtracking and longer chains appear without reasoning demonstrations. Production recipes add cold-start SFT and later preference stages for readability.

Trade-offs

  • pro: the reward is hard to fool when the verifier is sound, so RL can run far longer than against a learned reward.
  • con: only covers tasks with a checker. Weak verifiers get hacked too (tests that pass trivially, answers parsed out of malformed text), and a group where every sample scores the same gives zero advantage and no gradient.

How it works

  • Constitutional AI: a supervised phase where the model critiques and revises its own responses against written principles and is fine-tuned on the revisions, then an RL phase where an AI judge produces the preference labels (RLAIF). See Bai et al. 2022.
  • Logit distillation: train the student on the teacher's full softened distribution (KL to teacher logits). Rich signal per token, but needs teacher logits and a shared vocabulary.
  • Sequence-level distillation: the teacher generates complete outputs, the student runs plain SFT on them. Works across tokenizers and through an API; this is how R1 was distilled into Qwen and Llama students (about 800k samples, SFT only).
  • Distillation vs RL at small scale: in the R1 paper, the distilled Qwen-32B scored 72.6 on AIME 2024 pass@1 versus 47.0 for the same base trained with large-scale RL.

Trade-offs

  • pro: AI labels scale past human annotation budgets; principles become explicit and editable.
  • con: the student inherits teacher errors and judge biases, and cannot exceed its teacher on the distilled skill. Check provider terms before training on another vendor's outputs.

How it works

  • Update math: W = W0 + (α/r) · BA with B ∈ ℝd×r, A ∈ ℝr×k, r ≪ min(d, k). B starts at zero so training begins exactly at the base model. Trainable parameters per matrix drop from dk to r(d + k).
  • Scale: for a 4096 × 4096 projection at r = 16, that is 131,072 instead of 16.8M parameters, under 1%. On GPT-3 175B the LoRA paper reports ~10,000× fewer trainable parameters and ~3× less GPU memory.
  • Serving: merge BA into W0 for zero added latency, or keep adapters separate and hot-swap many tasks over one base.
  • QLoRA: freeze the base in 4-bit NF4 with double-quantized scales, backpropagate through it into 16-bit adapters, page optimizer state. The paper fine-tunes a 65B model on one 48GB GPU. See Dettmers et al. 2023.

Trade-offs

  • pro: cheap, reversible, composable; excellent for format, style, tool-call schemas and narrow classification.
  • con: a low-rank delta reshapes existing capability well but adds new factual knowledge or new skills poorly, and full-parameter training usually wins on large shifts such as a new language or domain. It can still erode safety behavior learned upstream.

Decision boundary

Use when

  • SFT: you can write the exact output you want for representative inputs.
  • DPO: you can say which of two outputs is better more easily than write the ideal one, and want a stable offline run.
  • RLVR: correctness is mechanically checkable and the base already solves the task some of the time.
  • Distillation or LoRA: a big model already does the task and you need it cheaper, or the change is format, tone or a narrow skill.

Skip when

  • The gap is missing or fresh knowledge: retrieval fixes that better than any stage here, see fine-tune vs RAG vs prompt.
  • You have no held-out eval that measures the target behavior; every method here optimizes something you cannot see.
  • RL with a learned reward on a small team: PPO tuning cost rarely pays off over DPO.
  • RLVR on a task where the base model never succeeds: zero pass rate means zero signal.

Worked example

The DPO loss with prompt-token masking, written against a Hugging Face–style causal LM in PyTorch. For clarity it assumes one unpadded sequence per call and a shared prompt length; production code (for example TRL's DPOTrainer) batches and handles padding. Log the reward accuracy and margin, not only the loss.

import torch
import torch.nn.functional as F

def seq_logprob(model, input_ids, prompt_len):
    # log p(response | prompt), summed; prompt tokens are masked out
    logits = model(input_ids).logits[:, :-1]   # position t predicts token t+1
    targets = input_ids[:, 1:]
    logp = torch.log_softmax(logits.float(), dim=-1)
    tok = logp.gather(-1, targets.unsqueeze(-1)).squeeze(-1)
    mask = torch.zeros_like(tok)
    mask[:, prompt_len - 1:] = 1.0             # first response token onward
    return (tok * mask).sum(-1)

def dpo_loss(policy, ref, chosen, rejected, prompt_len, beta=0.1):
    pc = seq_logprob(policy, chosen, prompt_len)
    pr = seq_logprob(policy, rejected, prompt_len)
    with torch.no_grad():                        # frozen SFT reference
        rc = seq_logprob(ref, chosen, prompt_len)
        rr = seq_logprob(ref, rejected, prompt_len)
    margin = beta * ((pc - rc) - (pr - rr))        # implicit reward gap
    loss = -F.logsigmoid(margin).mean()
    stats = {
        "reward_acc": (margin > 0).float().mean().item(),
        "margin": margin.mean().item(),
        "chosen_logp_shift": (pc - rc).mean().item(),  # <0 means both falling
    }
    return loss, stats

Reading the numbers: at step 0 the policy equals the reference, so the margin is 0 and the loss is log 2 ≈ 0.693. Reward accuracy climbing toward 1 while chosen_logp_shift goes negative is the "both likelihoods fall" pattern: the model is learning to avoid rejected text, not to produce the chosen text.

Failure modes

  • Template mismatch · fine-tuning or serving with a different chat template than training · missing stop tokens, leaked role tags, runaway generations
  • Unmasked prompts in SFT · the model learns to imitate user turns and system prompts · check that labels are −100 outside assistant spans
  • Reward hacking · proxy reward climbs while quality falls · track length and held-out human or judge preference alongside reward, and raise β if KL explodes
  • Eval contamination · benchmark items in pretraining or synthetic SFT data inflate scores · decontaminate by n-gram overlap and keep a private eval set
  • Safety erosion · a small benign fine-tune can weaken refusals learned in post-training · re-run red-team and guardrail evals after every tuning run
  • Catastrophic forgetting · narrow tuning degrades general skills · mix in general data, keep LoRA rank and learning rate modest, eval outside the target task

Keep in mind

  • Pretraining buys capability; post-training mostly selects and shapes behavior already latent in the base.
  • Chinchilla is ~20 tokens per parameter for training compute; deployed models overtrain on purpose for cheaper inference.
  • SFT imitates, preference methods rank, RLVR verifies: pick by the signal you can actually produce.
  • DPO is RLHF's objective with the reward model solved away; the KL to the reference is still there as β.
  • Every learned reward gets hacked eventually; verifiers get hacked more slowly.
  • LoRA reshapes behavior cheaply; it is a poor way to add knowledge.
