Transformer architecture

A decoder-only transformer is a stack of identical blocks that read from and write back into one residual stream; attention moves information between positions, the MLP transforms each position on its own.

In this chapter Derive attention from Q, K and V, size the KV cache under MHA, MQA and GQA, place RoPE, RMSNorm, SwiGLU and mixture-of-experts in the block, and explain why long context costs what it does.

Why the block matters

  • Memory math: KV cache size, and therefore batch size and max context per GPU, falls straight out of layer count, KV heads and head dimension. You cannot size a deployment without it.
  • Model cards: "70B dense", "47B total / 13B active", "GQA-8", "RoPE base 500k", "128k via YaRN" are architecture claims with direct cost and quality consequences.
  • Long-context reality: quadratic prefill, bounded sliding windows and extended positions explain why a model accepts 128k tokens yet degrades or slows well before that.
  • Beyond the loop: How LLMs actually work treats the network as a next-token scorer; this chapter opens the scorer.

Inside one decoder block

Token ids become vectors of width d (the model dimension) via an embedding lookup. That vector is the . Every block applies two pre-normed sublayers that each add their output back; after the last block a final norm and the unembedding matrix produce logits over the vocabulary. Read the stack top to bottom as one block.

  1. RMSNormrescale the stream to unit RMS with a learned gain; no mean subtraction, no bias
  2. Attention (GQA + RoPE)project to Q, K, V; rotate Q and K by position; causal softmax(QKᵀ/√dk)V per head; output projection WO
  3. Residual addx ← x + Attn(Norm(x)): the only path where information crosses positions
  4. RMSNormsecond pre-norm, independent gain
  5. MLP (SwiGLU) or MoEWdown(SiLU(xWgate) ⊙ xWup), applied to each position independently; MoE swaps in k of E routed experts
  6. Residual addx ← x + MLP(Norm(x)); repeat for all L blocks

How it works

  • Projections: per head, Q = xWQ, K = xWK, V = xWV, each T × dk with dk = d / H typically. Query asks, key advertises, value is what gets copied.
  • Scores: S = QKᵀ / √dk. If q and k components have unit variance, their dot product has variance dk; dividing by √dk keeps logits in a range where softmax does not saturate and gradients survive.
  • Causal mask: set Sij = −∞ for j > i before the row-wise softmax, so position i depends only on positions ≤ i. That is what lets training and prefill compute all T positions in one pass with the same result as sequential decode.
  • Mix and write: output = softmax(S)V, heads concatenated, multiplied by WO and added to the residual stream. Attention is the only sublayer that moves information between positions.
  • Embeddings: input embedding is a V × d lookup; the unembedding maps d → vocabulary logits. Some models tie the two matrices, many large ones do not.

Trade-offs

  • pro: fully parallel over positions during training and prefill, unlike recurrence.
  • con: attention scores scale as T² per head per layer; decode is linear per token but must stream the whole KV cache from memory each step.

How it works

  • MHA: H query heads, H key heads, H value heads. Each head can attend to a different relation.
  • MQA: H query heads share one K and one V head. Cache shrinks by H×; quality and training stability can drop.
  • : G KV heads, each shared by H/G query heads. The GQA paper also up-trains existing MHA checkpoints into GQA with a small fraction of the original pretraining compute.
  • Cache formula: bytes per token = 2 (K and V) × L × G × dhead × bytes per element. Query heads do not appear: they are never cached.

Trade-offs

  • pro: decode is usually memory-bandwidth bound; fewer KV bytes means more concurrent sequences and faster steps. Serving-side paging and quantization are in inference serving.
  • con: attention FLOPs barely change, since every query head still scores every key; GQA buys memory and bandwidth, not prefill compute.

How it works

  • Why needed: without a mask or position signal, attention is permutation-equivariant. The causal mask leaks some order, not enough.
  • Absolute: the original transformer added fixed sinusoids to the input embedding; GPT-2-style models learn a position table. Both hard-cap or degrade past the trained length.
  • : split q and k into 2-D pairs; rotate pair i at position m by angle m·θi, θi = base−2i/d. Then qm·kn depends on m − n. Applied inside every attention layer to Q and K only, never to V or the residual stream.
  • Context extension: position interpolation rescales indices so a longer sequence maps into the trained angle range, then fine-tunes briefly. YaRN interpolates per frequency band (high-frequency pairs left mostly intact, low-frequency pairs stretched) and adjusts attention temperature, needing far less data. Raising the RoPE base is another common lever; exact recipes are model-specific.

Trade-offs

  • pro: relative position for free, no extra parameters, works with the KV cache since cached keys are already rotated.
  • con: an advertised window is not an effective window; extended models can pass needle tests and still reason poorly at depth. Evaluate at your real length, see context budgeting.

How it works

  • Pre-norm: x + f(Norm(x)) instead of the original post-norm Norm(x + f(x)). The residual path stays an identity, so gradients reach early layers cleanly in deep stacks; a final norm precedes the unembedding.
  • RMSNorm: x / √(mean(x²) + ε) · g. Drops LayerNorm's mean subtraction and bias; cheaper and empirically as good.
  • SwiGLU MLP: Wdown(SiLU(xWgate) ⊙ xWup). Three matrices instead of two, so the hidden width is shrunk (often toward ~8/3·d, model-specific) to keep parameters comparable to a 4d two-matrix MLP.
  • Parameter intuition: attention ≈ 4d² per layer with MHA (less with GQA), a 4d MLP ≈ 8d², so a dense model ≈ 12·L·d² plus V·d per embedding matrix. GPT-3's L = 96, d = 12,288 gives ≈ 174B of its 175B.

Trade-offs

  • con: pre-norm lets the residual stream norm grow with depth; some models add extra norms (for example on Q and K) to tame it. Vendor-specific.

How it works

  • Router: a linear layer scores E experts per token; the top-k are run and their outputs summed, weighted by the normalized router scores. Attention stays dense and shared.
  • : Mixtral 8x7B has 8 experts per layer, top-2, 47B total and 13B active per token. Compute tracks active; memory tracks total.
  • Load balancing: without pressure the router collapses onto a few experts. Common fixes: an auxiliary loss rewarding uniform routing (Switch Transformer style), capacity limits that drop or overflow tokens, or bias-adjusted routing without an auxiliary loss (used by some recent models).
  • Variants: fine-grained experts (many small ones, higher k) and always-on shared experts are common in recent open models; details differ per family.

Trade-offs

  • pro: more capacity per FLOP; quality of a larger dense model at a smaller per-token compute bill.
  • con: all experts must be resident; expert parallelism adds all-to-all traffic; at large batch most experts are touched every step, so bandwidth savings shrink. Fine-tuning can disturb routing, see fine-tune or not.

How it works

  • Cost shape: per token and layer, score work (QKᵀ and weights·V) is about 4·T·d FLOPs versus about 24·d² for the projections and a 4d MLP. Rule of thumb for a dense MHA model: attention scores dominate only once T exceeds roughly 6·d, which is why short prompts feel linear and very long ones do not.
  • : tiles Q, K, V into on-chip SRAM and keeps a running max and sum (online softmax), so the T × T matrix is never written to HBM. Exact attention, not an approximation; memory becomes linear in T, FLOPs stay quadratic, wall-clock drops because the kernel was IO-bound.
  • Sliding-window attention: each token attends only to the last W positions. Per-layer cost and KV cache become O(W); stacked layers still propagate information up to roughly L·W back. Some models interleave local-window and global layers.

Trade-offs

  • pro: FlashAttention is a drop-in kernel; sliding windows cap memory for unbounded streams.
  • con: windowed layers cannot directly retrieve a fact beyond W; recall over very long inputs depends on the global layers.

Decision boundary

Use when

  • Choosing a self-hosted model: compare KV bytes per token and total vs active params, not only benchmark scores.
  • Planning GPU memory: weights plus KV cache × concurrent sequences × context length must fit.
  • Evaluating long-context claims: check position scheme, extension method and windowed layers before trusting the number.
  • Debugging latency: split prefill (compute, T²) from decode (bandwidth, KV size).

Skip when

  • You only call a hosted API: price per token already folds in architecture; reason with tokens and cost.
  • Inferring behavior from architecture alone: data and post-training dominate quality differences between similar shapes.
  • Reading per-layer or per-head stories into a model: interpretability claims need measurement, not block diagrams.
  • Hand-writing attention for production: use framework kernels (SDPA, FlashAttention) unless you are building kernels.

Worked example

NumPy grouped-query attention with a causal mask, then the KV-cache formula on the Llama 2 70B shape. Runnable as is; it prints the output shape and the three cache sizes from the table above.

import numpy as np

def gqa_attention(x, Wq, Wk, Wv, Wo, n_heads, n_kv):
    T, d = x.shape
    hd = d // n_heads
    q = (x @ Wq).reshape(T, n_heads, hd).transpose(1, 0, 2)  # (H, T, hd)
    k = (x @ Wk).reshape(T, n_kv, hd).transpose(1, 0, 2)     # (G, T, hd)
    v = (x @ Wv).reshape(T, n_kv, hd).transpose(1, 0, 2)
    rep = n_heads // n_kv                          # query heads per KV head
    k, v = np.repeat(k, rep, axis=0), np.repeat(v, rep, axis=0)
    s = q @ k.transpose(0, 2, 1) / np.sqrt(hd)        # (H, T, T)
    future = np.triu(np.ones((T, T), dtype=bool), k=1)
    s = np.where(future, -np.inf, s)               # causal mask
    w = np.exp(s - s.max(-1, keepdims=True))
    w /= w.sum(-1, keepdims=True)                 # row-wise softmax
    out = (w @ v).transpose(1, 0, 2).reshape(T, d)  # concat heads
    return out @ Wo

def kv_bytes_per_token(layers, n_kv, head_dim, bytes_per=2):
    return 2 * layers * n_kv * head_dim * bytes_per  # K and V

rng = np.random.default_rng(0)
T, d, H, G = 6, 64, 8, 2
x = rng.normal(size=(T, d))
Wq, Wo = (rng.normal(size=(d, d)) / 8 for _ in range(2))
Wk, Wv = (rng.normal(size=(d, G * d // H)) / 8 for _ in range(2))
print(gqa_attention(x, Wq, Wk, Wv, Wo, H, G).shape)  # (6, 64)

for name, g in [("MHA", 64), ("GQA-8", 8), ("MQA", 1)]:
    print(name, kv_bytes_per_token(80, g, 128) // 1024, "KiB/token")
# MHA 2560, GQA-8 320, MQA 40

Failure modes

  • Sizing GPUs from weights alone · KV cache × batch × context often exceeds the weights at long context · compute it per model with the formula above
  • Reading "47B MoE" as "47B of compute" or "13B of memory" · compute follows active, memory follows total
  • Trusting the advertised context window · extended RoPE and windowed layers can accept tokens the model barely uses · test retrieval and reasoning at your real depth
  • Expecting GQA to speed up prefill · it cuts KV bytes, not attention FLOPs · long-prompt latency still scales with T²
  • Calling FlashAttention an approximation · it is exact; approximate and sparse attention are different methods with quality trade-offs
  • Off-by-one causal masks in custom code · a leaked future token makes training loss look excellent and generation fail

Keep in mind

  • The residual stream is the bus; attention mixes positions, the MLP transforms each one.
  • softmax(QKᵀ/√dk + causal mask)V, and only K and V are cached.
  • KV bytes per token = 2 × layers × KV heads × head dim × bytes; GQA shrinks the middle factor.
  • RoPE rotates Q and K so scores depend on relative offset; extension rescales those angles.
  • Dense parameters ≈ 12·L·d²; MoE separates total (memory) from active (compute).
  • FlashAttention fixes memory traffic, not the T² arithmetic; sliding windows bound the cache.
