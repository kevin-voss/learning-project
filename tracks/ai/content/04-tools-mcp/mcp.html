MCP · Model Context Protocol

MCP is an open protocol that connects AI apps to tools and data. Write the server once, every client gains it, and the tool menu builds itself at runtime from what the server reports.

In this chapter Trace the host, client and server roles, capability negotiation, transport and authorization boundary in an MCP integration.

Why this layer matters

  • N×M trap: M apps × N tools means M×N bespoke integrations to maintain.
  • Plugin sprawl: every app invented its own plugin format.
  • Opaque REST: schemas and usage notes live in docs models cannot read.
  • Precedent: collapsed editors × languages into M+N.

Protocol architecture

Three ways to expose tools to models, cheapest first.

How it works

  • Declare JSON Schemas with each request, your loop executes calls (tool calling).
  • Zero handshake, zero extra hops, lowest latency of the three.

Trade-offs

  • pro: fastest path while tools live in one app on one machine.
  • con: re-implemented per app, the N×M trap. Menu frozen at build time.

How it works

  • Host spawns the server, flows over stdin/stdout.
  • No network hop, but a launched server is trusted executable code: scope its environment and access. Ideal for files, shell, dev databases.
  • gotcha stdout IS the wire: a stray print() hangs the server. Log to stderr.

Trade-offs

  • pro: one server feeds Claude Desktop, Cursor and goose.
  • con: per-process, wrong shape for multi-user SaaS backends.

How it works

  • Streamable HTTP carries JSON-RPC over HTTP; streaming and long-running work follow what both sides negotiate. The current core uses self-contained, stateless requests with per-request capability negotiation.
  • Remote authorization follows the MCP authorization specification and its OAuth requirements for the negotiated version; check the current spec rather than assuming one fixed flow.

Trade-offs

  • pro: one hosted server shared across teams and machines.
  • con: now a web service: rate limits, audit logs, secrets scoping.
  • con: envelope overhead, keep hot loops native (ops).

Protocol primitives and control

  • Tools: callable functions with input schemas. The host/client mediates model-proposed calls and enforces consent and authorization; tool annotations are hints, not enforcement.
  • Resources: context addressed by resource identifiers; the host decides what reaches the model or user.
  • Prompts: reusable templates a host may surface for the user or the application.

The protocol also covers progress, cancellation and error reporting. Optional client features such as sampling or elicitation exist only when negotiated for the current protocol version.

Decision boundary

Use when

  • Tools are shared across apps, teams or machines.
  • The consumer is a model, not a developer reading docs.
  • The tool menu must change without shipping client code.

Skip when

  • One app, one machine, tools never leave it.
  • High-frequency inner loops feel the handshake overhead.
  • Only your own code calls the endpoint, never a model.
  • You cannot audit what a remote server exposes.

Worked example

Illustrative Python SDK shape, not a pinned recipe: SDK APIs change, so check the official quickstart and the generated tool schema before deploying. Debug the host-client-server exchange before blaming the model.

from mcp.server.fastmcp import FastMCP

mcp = FastMCP("tools")          # one server, every MCP client

@mcp.tool()
def get_weather(city: str) -> str:
    """Current weather for a city."""     # docstring = description
    return fetch_weather(city)

mcp.run()   # stdio locally · streamable HTTP for remote

# debug: npx @modelcontextprotocol/inspector python fastmcp_server.py
  • One server can serve several compatible hosts, subject to each host’s protocol version, trust policy and tool permissions.
  • GitHub, Sentry, Stripe ship public MCP servers agents call directly.

Failure modes

  • Trust decision: a remote server shapes what your model sees and does.
  • Injection: tool results and resources are untrusted input (injection).
  • Over-exposure: drop table next to read row is one confused model away.
  • stdio corruption: third-party library prints break the wire too.

Keep in mind

  • MCP standardizes host-client-server messages; compatibility still needs matching protocol versions, capabilities, transports and authorization.
  • Keep protocol discovery separate from consent and authorization; a declared capability does not grant permission.
  • Lifecycle depends on the protocol version you target: earlier versions open each session with an initialize handshake before tools/list and tools/call. Check the spec for that version.
  • stdio: stdout is the wire, logging goes to stderr.
  • Debug in the Inspector before blaming the client.
