Agent patterns

A chain runs a fixed sequence of prompts you wrote. An agent runs a goal: a loop that thinks, acts through tools, observes and picks the next step itself. Extra agents are a team you may not need. This page covers the ladder, the handoff mechanics and the honest reasons to climb.

In this chapter Compare direct tool loops, routers, planners and multi-agent handoffs by control complexity, failure surface and measurable benefit.

Why this layer matters

  • Goals, not prompts: "research this market, write a brief" is steps, decisions, retries.
  • Context landfill: after 40 tool calls one window is a swamp, see context budget.
  • Runtime control: a chain follows your flowchart, an agent picks steps at runtime.
  • Rule zero: start single. Every extra agent is a distributed-systems bug you chose.

Control patterns

Four escalation shapes, one rung each. Climb only when the rung below measurably hurts.

How it works

  • loop: think, act, observe, repeat until done.
  • Stop condition and step budget enforced in the loop, not in hope.
  • Trim stale tool outputs so the goal stays visible.

Trade-offs

  • Cheap, debuggable, surprisingly far. Claude Code and Cursor are this shape.
  • Most "multi-agent" products are a single agent wearing a costume.
  • Diverging intents: classify once, dispatch to specialist prompts (a router).

How it works

  • The planner emits an inspectable step list, the executor works through it.
  • Failures trigger replanning, not silent drift from the plan.
  • The plan artifact makes runs auditable, see graphs.

Trade-offs

  • Worth it when the plan must be reviewable and revisable.
  • Single-step asks: planning is pure overhead.

How it works

  • A manager plans, delegates, merges, iterates. For big parallelizable jobs.
  • The manager's context stays clean while workers absorb tool noise.
  • Fan out only for independent subtasks, like five competitors at once.

Trade-offs

  • Tokens multiply per hop: briefs, results, merges re-describe the world.
  • Latency stacks: plan, delegate, wait, merge is the slow path.
  • A supervisor re-reading every worker output gains zero isolation.

How it works

  • Triage hands the billing case to the billing specialist, mid-journey.
  • Travels: task summary, distilled ids and artifacts, decisions, constraints.
  • Never the transcript. A schema'd message shaped like a tool call, see tool calling.
  • Returns: result plus a short trail, so the user repeats nothing.

Trade-offs

  • Information loss compounds per hop. Re-asking users means a too-thin schema.
  • Cap handoffs per run. A-to-B-to-A loops need a breaker, see ops.

Two questions before you multiply agents.

Decision boundary

Use multi when

  • Isolation: each subagent starts clean and returns only the result.
  • Parallelism: five competitors or 50 eval cases at once, see evals.
  • Model per role: cheap model for breadth, strong model for the merge.
  • Conflicting tools: read-only researcher vs write-enabled fixer.

Skip multi when

  • One intent, one domain. A single agent with tools suffices.
  • Latency-sensitive chat cannot afford plan, delegate, wait, merge.
  • You cannot name which reason each extra agent serves. Theater.
  • Every hop costs tokens and multiplies failure odds.

Worked example

Loop, tools, goal, stop condition: the entire agent in eight lines. Everything else on this page is escalation. A handoff is one tool call whose payload is the brief.

def run_agent(goal, tools, max_steps=25):
    state = {"goal": goal, "history": []}
    for step in range(max_steps):        # budget in code, not in hope
        reply = llm(state, tools)        # thinks, may request tool calls
        if not reply.tool_calls:         # no tool requested: done
            return reply.text
        state["history"].append(run_tools(reply.tool_calls))
    raise BudgetExceeded("max steps hit, goal not met")

Failure modes

  • Token amplification: every hop re-describes the world, see tokens and cost.
  • Error multiplication: five agents at 95% land near 77% end to end.
  • Handoff amnesia: forwarding the transcript or nothing. Send summary plus artifacts.
  • Ping-pong loops: cap handoffs per run like any other budget.
  • Router drift: silent misroutes. Log the route with every answer.

Keep in mind

  • Start single agent, escalate only with a named reason.
  • Agent = loop + tools + goal + stop condition + budget.
  • Handoffs carry summary, artifacts, constraints. Never full history.
  • Log every route and every handoff alongside the answer.
  • Isolation, parallelism, model-per-role. Any other reason is hype.

Try, verify, explain

  1. Take a task with a fixed three-step workflow and one uncertain research step. Decide where deterministic code ends and model-controlled planning begins; justify the extra failure surface.
  2. Run the same task 10 times as a single agent and as a supervisor with 3 workers. Log total input tokens, wall-clock time and success rate per run, then check the observed success against p^hops (0.955 ≈ 0.77).
  3. Explain why a supervisor that re-reads every worker’s full output gains no context isolation, and what a handoff payload must carry so the receiving agent never re-asks the user.
