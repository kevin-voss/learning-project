The ecosystem

A new framework ships every quarter and each demo looks like production in a three-minute video. The way out is boring: name the job, then pick the tool whose core abstraction matches it.

Problemoption overload, churn, lock-in fear
  • Option overload: a dozen frameworks, runtimes and SDKs all claim to be the agent layer. Teams pick by brand or hype.
  • Churn: abstractions rename between versions, imports move, old answers rot. Yesterday's tutorial is today's build error.
  • Lock-in fear: adopt a runtime and your prompts, tools and state start living inside its concepts. Migration later is a rewrite of the glue.
  • Raw-dogging costs too: hand-writing retries, streaming parsers, JSON repair, retrieval glue and tracing is a fun weekend and a bad quarter.
  • The real risk: building the product inside abstractions nobody on the team can debug at 2am.
Solutionpick by job, keep the raw API close
  • Pick by job, not by brand. Name the job first: assemble RAG, run an agent graph, embed a copilot in your app, run a CI agent. Then take the tool built for exactly that.
  • Keep the raw API in your back pocket. Prefer tools that never lock you away from plain model calls. The day the framework fights you, you drop one layer, not the system.
  • Own the harness. Prompts, tools, permissions and evals are yours regardless of framework. That is where the quality lives, invest there.

The 100-line reality check: any agent loop is call model, parse tool calls, execute, append, repeat, with a budget. You could write it this afternoon. Frameworks earn their keep in the ten thousand lines around the loop: durability, streaming, integrations, tracing. Judge them on that, not on the demo.

Howlangchain · langgraph · cursor sdk · goose · adjacent tools

LangChain: the integration supermarket

  • Abstractions: chains that compose steps, tools that wrap functions, memory that carries chat history, plus 100+ integrations for models, vector stores and loaders.
  • Fast start: a standard RAG pipeline in twenty lines that would take a week raw. For prototypes and standard shapes this speed is real.
  • The abstraction tax: layers of wrappers hide the actual prompt and the actual calls, stack traces get deep, and versions churn under you. Debugging often means reading framework source.
  • Fair verdict: great for prototypes and conventional pipelines, risky as a deep architectural commitment. Pin versions, turn tracing on so you can see what it generates, keep escape hatches.

LangGraph: graphs as code

  • Idea: the orchestration model from graphs as a library. Nodes, edges, conditional routes and state reducers, all plain code you can read, test and diff.
  • Checkpointing built in: persist state per step to Postgres, get resume, time-travel debugging and human interrupts. The operating mechanics are the durable ops page.
  • Explicit over implicit: no hidden agent magic. The topology is visible, which is exactly what you want when a run misbehaves in production.
  • Watch: a real learning curve, and snapshots bloat if you shovel documents into state. Simple linear chains are still better served by a plain queue.

Cursor SDK and the agent-SDK family

  • What: drive a coding agent loop from your own code. TypeScript and Python SDKs, a headless CLI, and cloud agents running in isolated VMs.
  • Inherits infrastructure: your agent gets codebase indexing, search, MCP tool support and checkpoints. Your app sends a prompt plus tools and gets edits back.
  • CI primitive: the CLI in headless mode, agent -p with --output-format json, is the autofix bot. Auth via an API key from your secrets manager, never the repo.
  • Family: Claude Code (SDK plus CLI) and OpenAI Codex CLI share the same shape, the coding agent as a programmable service.
  • Watch: with managed offerings your code context lives in their cloud. Check your data policy before the first run, and see full systems on AWS for where such bots usually land.

goose: the open-source runtime you own

  • What: an open-source agent runtime in Rust (born at Block, now under the Linux Foundation's Agentic AI Foundation). CLI, desktop app and a scriptable daemon, Apache-2.0.
  • MCP-native extensions: its extensions ARE MCP servers. Any server you build plugs into goose and every other MCP client, so your tooling compounds across runtimes.
  • Local-first: 15+ model backends including local Ollama, which makes air-gapped work possible. Provider-neutral by design.
  • Recipes: workflows as portable YAML, instructions plus extensions plus parameters. Shareable, runnable in CI, schedulable (a morning code review on a cron).
  • Safety rails: tool permission controls, sandbox mode and prompt-injection detection. You still run it yourself: updates, permissions and sandboxing are your job.

adjacent tools worth knowing

  • LlamaIndex: RAG-first: ingestion, parsers, indexes, retrievers. RAG-centric defaults everywhere.
  • DSPy: prompts as programs, compiled against your evals. Compiled prompts look weird, trust the metrics.
  • Instructor + Pydantic: typed outputs with validation retries on top of tool calling and structured output. Retries add hidden latency.
  • Vercel AI SDK: TypeScript streaming UIs and tool-call rendering. Frontend-first by design.
  • MCP SDKs and FastMCP: build one tool server and every client can use it. The glue topic is MCP.

Lock-in is a loan you take silently. Prompts as framework objects, tools as framework types, state in a proprietary store: each one raises migration cost. Mitigate early: tools over MCP so they outlive the framework, prompts as plain files, model calls behind your own thin adapter, checkpoints you can export. Ask the exit question before adopting: what does leaving cost, in days?

from langgraph.graph import StateGraph

g = StateGraph(dict)
g.add_node("plan", plan_step)          # nodes are plain functions
g.add_node("act", act_step)            # tool calls happen here
g.add_edge("plan", "act")
g.add_conditional_edges("act", route)  # code picks the next node
app = g.compile(checkpointer=pg_saver) # durability per step

const cursor = new CursorClient();
const conv = await cursor.startConversation({ mode: "agent" });
const res = await conv.prompt(

);

Pitfallsdemos, taxes, mortgages
  • Picking by demo: the three-minute video never shows retry storms, eval harnesses or migration day. Demand the failure story before adopting.
  • Abstraction tax at 2am: when the framework breaks you read its source. Budget team time for that, or keep the stack shallow.
  • Hidden latency: framework retry and validation layers can double your p99 without a trace. Trace through the abstraction, not around it.
  • Lock-in creep: each proprietary concept adopted is a small mortgage on migration day. Export early, adapter always.
  • Cloud code context: managed agents ship repo slices to their infrastructure. Policy check before the first run, not after.
  • Unpinned deps: minor upgrades rename core imports. Lockfile, pin, upgrade on purpose with the changelog open.
  • Rewriting the loop for pride: the loop is 100 lines, but the surrounding 10,000 are why teams adopt runtimes. Write raw only when you truly need the control.
Checklistsix bullets to remember
  • Name the job before the tool: pipeline, graph, copilot, CI agent
  • Keep a raw-API scratch file so the escape hatch always works
  • Build tools over MCP so they outlive any framework
  • Prompts in plain files, model calls behind your own adapter
  • Pin versions, read changelogs, upgrade deliberately
  • Ask the exit question early: what does leaving cost, in days?
