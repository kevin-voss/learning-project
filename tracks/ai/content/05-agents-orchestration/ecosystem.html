The ecosystem

A new framework ships every quarter, and every demo looks like production in a three-minute video. The way out is boring: name the job, then pick the tool whose core abstraction matches it.

In this chapter Evaluate framework boundaries and abstractions by the control they provide, operational cost and portability requirements.

Problemoption overload, churn, lock-in fear

  • Option overload: a dozen frameworks, runtimes and SDKs claim to be the agent layer; teams pick by brand or hype.
  • Churn: abstractions rename, imports move, yesterday's tutorial is today's build error.
  • Lock-in fear: adopt a runtime and your prompts, tools and state start living inside its concepts; migrating later rewrites the glue.
  • Raw-dogging costs too: hand-written retries, streaming parsers, JSON repair, retrieval glue and tracing are a fun weekend and a bad quarter.
  • The real risk: building the product inside abstractions nobody on the team can debug at 2am.

Solutionpick by job, keep the raw API close

  • Pick by job, not by brand. Name it first (assemble RAG, run an agent graph, embed a copilot, run a CI agent), then take the tool built for exactly that.
  • Keep the raw API in your back pocket. Prefer tools that never lock you away from plain model calls; when the framework fights you, you drop one layer, not the system.
  • Own the harness. Prompts, tools, permissions and evals are yours whatever the framework. Quality lives there; invest there.

The 100-line reality check: any agent loop is call model, parse tool calls, execute, append, repeat, within a budget. You could write it this afternoon. Frameworks earn their keep in the ten thousand lines around it: durability, streaming, integrations, tracing. Judge them on that, not on the demo.

Howlangchain · langgraph · cursor sdk · goose · adjacent tools

LangChain: the integration supermarket

  • Abstractions: chains compose steps, tools wrap functions, memory carries chat history, plus 100+ integrations for models, vector stores and loaders.
  • Fast start: a standard RAG pipeline in twenty lines that would take a week raw. For prototypes and standard shapes, the speed is real.
  • The abstraction tax: wrappers hide the actual prompt and calls, stack traces get deep, versions churn. Debugging often means reading framework source.
  • Fair verdict: great for prototypes and conventional pipelines, risky as a deep architectural commitment. Pin versions, trace what it generates, keep escape hatches.

LangGraph: graphs as code

  • Idea: the graphs orchestration model as a library: nodes, edges, conditional routes and state reducers in plain code you can read, test and diff.
  • Checkpointing built in: persist state per step to Postgres for resume, time-travel debugging and human interrupts. Operating mechanics: durable ops.
  • Explicit over implicit: no hidden agent magic; the topology is visible when a run misbehaves in production.
  • Watch: a real learning curve, and snapshots bloat if you shovel documents into state. Simple linear chains are better served by a plain queue.

Cursor SDK and the agent-SDK family

  • What: drive a coding agent loop from your own code: TypeScript and Python SDKs, a headless CLI, cloud agents in isolated VMs.
  • Inherits infrastructure: codebase indexing, search, MCP tool support and checkpoints. Your app sends a prompt plus tools and gets edits back.
  • CI primitive: the headless CLI, agent -p with --output-format json, is the autofix bot. The API key comes from your secrets manager, never the repo.
  • Family: Claude Code (SDK plus CLI) and OpenAI Codex CLI share the shape: the coding agent as a programmable service.
  • Watch: managed offerings keep your code context in their cloud. Check your data policy before the first run; full systems on AWS shows where such bots usually land.

goose: the open-source runtime you own

  • What: an open-source agent runtime in Rust (born at Block, now under the Linux Foundation's Agentic AI Foundation): CLI, desktop app and scriptable daemon, Apache-2.0.
  • MCP-native extensions: its extensions ARE MCP servers, so any server you build works in goose and every other MCP client.
  • Local-first: 15+ model backends including local Ollama, so air-gapped work is possible. Provider-neutral by design.
  • Recipes: portable YAML workflows (instructions, extensions, parameters), shareable, runnable in CI and schedulable, e.g. a morning code review on a cron.
  • Safety rails: tool permission controls, sandbox mode and prompt-injection detection. Self-hosting means updates, permissions and sandboxing are your job.

adjacent tools worth knowing

  • LlamaIndex: RAG-first: ingestion, parsers, indexes, retrievers. RAG-centric defaults everywhere.
  • DSPy: prompts as programs, compiled against your evals. Compiled prompts look weird, trust the metrics.
  • Instructor + Pydantic: typed outputs with validation retries on top of tool calling and structured output. Retries add hidden latency.
  • Vercel AI SDK: TypeScript streaming UIs and tool-call rendering. Frontend-first by design.
  • MCP SDKs and FastMCP: build one tool server and every client can use it. The glue topic is MCP.

Lock-in is a loan you take silently. Prompts as framework objects, tools as framework types, state in a proprietary store: each raises migration cost. Mitigate early: tools over MCP, prompts as plain files, model calls behind your own thin adapter, exportable checkpoints. Before adopting, ask: what does leaving cost, in days?

Pitfallsdemos, taxes, mortgages

  • Picking by demo: the three-minute video never shows retry storms, eval harnesses or migration day. Demand the failure story first.
  • Abstraction tax at 2am: when the framework breaks, you read its source. Budget for that or keep the stack shallow.
  • Hidden latency: framework retry and validation layers can double p99 invisibly. Trace through the abstraction, not around it.
  • Lock-in creep: each proprietary concept adopted is a small mortgage on migration day. Export early, adapter always.
  • Cloud code context: managed agents ship repo slices to their infrastructure. Policy check before the first run, not after.
  • Unpinned deps: minor upgrades rename core imports. Lockfile, pin, upgrade on purpose with the changelog open.
  • Rewriting the loop for pride: the loop is 100 lines; the surrounding 10,000 are why teams adopt runtimes. Go raw only when you need the control.

Checklistsix bullets to remember

  • Name the job before the tool: pipeline, graph, copilot, CI agent
  • Keep a raw-API scratch file so the escape hatch always works
  • Build tools over MCP so they outlive any framework
  • Prompts in plain files, model calls behind your own adapter
  • Pin versions, read changelogs, upgrade deliberately
  • Ask the exit question early: what does leaving cost, in days?

Try, verify, explain

  1. Pick one framework abstraction you would keep and one you would replace with direct code. Explain the operational boundary and migration cost.
  2. Build the same one-tool task twice, as a raw HTTP loop and through one framework, with tracing on. Over 20 runs compare model calls and tokens per run, p50/p99 latency, and any retries or validation calls the framework added that you never wrote.
  3. Explain why tools exposed as MCP servers survive a framework migration while prompts stored as framework objects do not, then estimate in days what leaving your current stack would cost.
